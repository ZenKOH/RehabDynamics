# RehabDynamics

**Uncertainty-aware movement intelligence for rehabilitation biomechanics.**

RehabDynamics is a research-grade scaffold for turning OpenSim-compatible movement data into reproducible gait metrics, model-ready inputs, dynamics-provider outputs and explicit out-of-distribution (OOD) warnings. It is designed around the Stanford movement-AI ecosystem—particularly GaitDynamics, AddBiomechanics, OpenSim/Nimble Physics and OpenCap—without pretending that a healthy-gait foundation model is already validated for neurological rehabilitation.

> **Research use only.** RehabDynamics v0.1 is not a medical device, diagnostic system or treatment recommendation engine.

## Why this exists

The translational gap is not another gait dashboard. It is the missing layer between increasingly accessible movement capture and trustworthy rehabilitation biomechanics:

`video / motion capture / sensors → kinematics → dynamics model → validation + OOD guardrail → research interpretation`

GaitDynamics demonstrates powerful generative inference of gait kinematics and external forces, but pathological gait, smartphone-derived kinematics, assistive-device gait and robot-assisted walking require additional validation. RehabDynamics makes that validation problem a first-class software object.

## v0.1 capabilities

- Parse OpenSim `.mot`/tabular motion files into a canonical trial representation.
- Compute transparent kinematic QC and gait features.
- Screen obvious domain shifts with an auditable OOD rule engine.
- Escalate neurological/pathological or assistive-device contexts by default.
- Attach precomputed GaitDynamics/external dynamics through a clean file adapter.
- Run analyses from a CLI, FastAPI service or Streamlit research interface.
- Keep model provenance and limitations in every analysis result.
- Test and lint automatically on Python 3.10–3.12.

## What v0.1 deliberately does **not** do

- It does not diagnose disease or prescribe rehabilitation.
- It does not claim its OOD score is a calibrated probability.
- It does not bundle Stanford GaitDynamics source code or model checkpoints.
- It does not silently upload patient data to AddBiomechanics or any public service.
- It does not give an AI model control authority over a rehabilitation robot.

Those omissions are design decisions, not missing polish.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev,api,ui]'
pytest
```

Analyse an OpenSim motion file:

```bash
rehabdynamics analyse path/to/walk.mot --pathology healthy
```

Attach a precomputed dynamics file generated by an external GaitDynamics workflow:

```bash
rehabdynamics analyse path/to/walk.mot --predictions path/to/predicted_forces.mot
```

Run the API:

```bash
uvicorn rehabdynamics.api.main:app --reload
```

Run the research UI:

```bash
streamlit run src/rehabdynamics/ui/app.py
```

## Dataset strategy

No public dataset is copied into this repository. The benchmark layer is designed to register external datasets with provenance and licence metadata. Priority data sources:

1. **AddBiomechanics** — broad harmonised gait/movement corpus for reproduction and healthy-domain benchmarking.
2. **GaitDynamics held-out studies** — reproduce published external-force tasks before extending them.
3. **OpenCap + force-plate paired data** — test whether camera-derived kinematics preserve dynamics accuracy.
4. **Neurological gait cohorts** — stroke first, then other populations with explicit cohort-level validation.
5. **Robot/exoskeleton sessions** — shadow-mode research only until the human–robot domain is validated.

See [`docs/DATASETS.md`](docs/DATASETS.md).

## Validation programme

The core scientific question is not “does the model work on average?” It is:

> **At what distance from the healthy gait manifold does dynamics prediction become unreliable for rehabilitation use?**

The protocol therefore separates analytical validation, cross-capture validation, pathological-gait validation and prospective shadow-mode evaluation. See [`docs/VALIDATION_PROTOCOL.md`](docs/VALIDATION_PROTOCOL.md).

## Roadmap

- **Phase 0 — reproducibility:** harden parsing, environment, fixtures and upstream output interchange.
- **Phase 1 — benchmark:** reproduce healthy gait force estimation and publish failure surfaces.
- **Phase 2 — OpenCap bridge:** paired camera/MoCap/force-plate comparison.
- **Phase 3 — GaitDynamics-Neuro:** stroke domain-shift study, OOD model and careful fine-tuning.
- **Phase 4 — RehabDynamics clinical research platform:** longitudinal change and intervention-response research.
- **Phase 5 — Human–Robot Movement Model:** robot assistance as an explicit conditioning variable, initially in shadow mode.

See [`docs/ROADMAP.md`](docs/ROADMAP.md).
